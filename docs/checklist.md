# Implementation Checklist

Tracks execution against `docs/roadmap.md`, phase by phase. Where a phase
touches Django apps, the build order matches the dependency order fixed in
`docs/modules.md` (Layer 0 → 1 → 2 → 3) — don't start an app before the ones
above it in its list are done.

Check an item only once it's merged to `master` and passing CI, not when
it's "basically working locally." Update the status table in
`docs/roadmap.md` when an entire phase's boxes are checked.

---

## Definition of Done — per Django app

Apply this to every app below before checking it off:

- [ ] Models defined (`TenantScopedModel`/`TimeStampedModel`/`SoftDeleteModel` from `core` where applicable)
- [ ] Migrations generated and applied cleanly on a fresh DB
- [ ] `services.py` (writes) and `selectors.py` (reads) implemented — no other app reaches into this app's ORM directly
- [ ] DRF serializers + viewsets + router registered under `/api/v1/`
- [ ] Admin registration where useful for support/ops
- [ ] Permission classes applied (`IsAuthenticated` + tenant scoping + role checks)
- [ ] Unit tests for `services`/`selectors`; integration tests for API endpoints
- [ ] `import-linter` contract passes — no illegal cross-layer imports
- [ ] Added to `LOCAL_APPS` in `backend/config/settings/base.py`
- [ ] OpenAPI schema renders cleanly via `drf-spectacular`

  **Real, foundational issues surfaced by being the first app to actually use `TenantScopedModel`/`ModelViewSet`/`ModelSerializer` together** (all fixed in `core`/`api`, not worked around locally, since every one of the 7 remaining Phase 2 apps would hit the same thing):
  1. `TenantScopedModel` extended `UUIDPrimaryKeyModel` directly, with no `created_at`/`updated_at` — but docs/database.md §1 says timestamps are "not optional per-model." Never surfaced before because no app had used `TenantScopedModel` on a real model until now. Fixed: it now extends `TimeStampedModel` instead (still single inheritance, no manager-collision risk).
  2. DRF's class-level `queryset = Model.objects.all()` convention is incompatible with `TenantManager`, which raises `TenantContextMissing` *eagerly* the moment `.all()`/`.filter()` is called (verified/intentional per `core`'s own tests) — a class-body attribute evaluates at import time, before any request (and its bound tenant) exists, so it broke Django startup entirely. Fixed with a shared `api.viewsets.TenantScopedModelViewSet` — subclasses set `queryset_model`, and `get_queryset()` resolves it fresh per request instead, the standard DRF pattern for any per-request-dynamic queryset.
  3. `manage.py spectacular` schema generation (no real request, so no bound tenant) crashed twice more: DRF's `ModelSerializer` builds uniqueness validators for conditional `UniqueConstraint`s by calling `model._default_manager.filter(...)` directly — bypassing any view-level fix entirely. Fixed with a shared `api.serializers.TenantScopedModelSerializer` that skips validator generation when no tenant is bound (real requests always have one, so real validation is unaffected). Separately, `TenantManager`/`TenantScopedSoftDeleteManager`/`TenantScopedAllManager` didn't have a working `.none()` — third-party schema-introspection tooling calls `Model._default_manager.none()` directly, and `.none()` never touches real data anyway (Django's `EmptyQuerySet` short-circuits before hitting the DB), so it's now exempted from the tenant-bound check everywhere, with a regression test in `core`.
  4. django-filter's automatic `filterset_fields` goes one layer deeper still — `resolve_field()` calls `model_field.model._default_manager.all().query` purely to introspect a *related* field's type, still outside any bound tenant. Rather than reshaping `core`'s query-execution model further under time pressure (a bigger, higher-stakes change to a security-critical mechanism, deserving its own dedicated pass, not a rushed mid-feature fix), `filterset_fields` is deliberately not used here — an explicit `django_filters.FilterSet` with hand-declared filters (not auto-derived from `Meta.fields`) avoids the same crash and is the correct way to add filtering later, noted inline in `views.py`.
